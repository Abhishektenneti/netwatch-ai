## API service — fully implemented

### Config
- `NetwatchProperties` — typed config record for `netwatch.qdrant.*` and `netwatch.kafka.topics.*`.
- `QdrantConfig` — Qdrant gRPC client bean (read-only; collection creation stays in processor).
- `KafkaConfig` — topic declarations for `anomaly-events`, `explained-events`, `processed-events` + DLQ error handler.
- `JacksonConfig`, `build.gradle` — `JavaTimeModule`, actuator, explicit gRPC transitive deps.

### Data & services
- **`AlertRepository`** — bounded in-memory store (10k cap, LRU eviction). Indexes: `byEventId` (O(1)), `byDeviceId`, paginated `findAll`. `updateExplanation()` atomically replaces a record when the LLM result arrives.
- **`AlertService`** — three `@KafkaListener`s: (1) `anomaly-events` → store alert, (2) `explained-events` → attach explanation, (3) `processed-events` → per-device total event counter for accurate anomaly rate.
- **`DeviceService`** — Qdrant `RecommendPoints` finds nearest-neighbour devices by behaviour embedding; gracefully returns empty list if device has no embedding yet.

## GitHub Issue Automation

Set up a fully automated issue-to-PR pipeline driven by GitHub Actions and Claude Code — no external webhook server required.

### Labels

| Label | Purpose |
|---|---|
| `claude-enhancement` | Triggers Claude to implement a new feature |
| `claude-bug` | Triggers Claude to fix a bug |
| `claude-implementing` | Applied automatically while Claude is working; removed on PR merge |

### Workflows

**`.github/workflows/claude-implement.yml`** — triggered when `claude-enhancement` or `claude-bug` is applied to an issue:
1. Adds the issue to the GitHub Project board and sets status → **In Progress**
2. Applies `claude-implementing` label
3. Runs `anthropics/claude-code-action@beta` with a prompt that tells Claude to: explore the repo, implement the issue, create a branch (`issue-{N}-{slug}`), commit, push, and open a PR with `Closes #N` in the body

**`.github/workflows/project-sync.yml`** — triggered when a PR is merged:
1. Parses `Closes #N` / `Fixes #N` / `Resolves #N` references in the PR body
2. Sets the linked issue's project board status → **Done**
3. Removes the `claude-implementing` label

### Project Board

GitHub Projects v2 board: **NetWatch AI Development**

Status columns: `Todo → In Progress → In Review → Done`

Project operations (moving issues between statuses) use the GitHub GraphQL API via `GH_PROJECT_TOKEN`. The `GITHUB_TOKEN` built into Actions does not carry the `project` scope, so a separate PAT is required.

### Required Secrets and Variables

Set these in `Settings → Secrets and variables → Actions`:

| Type | Name | Value |
|---|---|---|
| Variable | `PROJECT_NUMBER` | The integer project number from `gh project create` |
| Secret | `ANTHROPIC_API_KEY` | Anthropic API key for Claude Code |
| Secret | `GH_PROJECT_TOKEN` | GitHub PAT with `project` + `repo` scopes |

### End-to-End Flow

```
Create issue
    → apply claude-enhancement or claude-bug label
        → workflow triggers
            → issue moves to In Progress on board
            → Claude implements, pushes branch, opens PR
                → PR merged
                    → issue moves to Done on board
```
